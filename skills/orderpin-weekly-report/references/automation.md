# 首次配置与自动运行

## 首次配置

正式周报收件人统一为骆华根，不再让员工选择。以下“收件人配置”指在当前工作组织中解析核对其账号，不是自由填写接收范围。月度候选与失败提醒仍仅给员工本人。

员工请求“配置自动周报”时由 Agent 完成以下步骤，不让员工手写配置或周报。已有明确答案不重复询问。

1. 检查 Git、Bash、DWS 及当前 Agent 的工作记录读取、调度能力。执行 `dws version`，按 dws-report.md 查询本人、工作组织、实时周报模板和收件人，解决同名歧义。不复制维护者账号或示例身份。
2. 一次收集缺失的配置：允许读取的 OrderPin 项目目录/工作会话、明确排除项、组织与账号、模板、周报收件人、时区、周五执行时间、首次覆盖起点、失败提醒渠道。月度候选提醒仅对本人，单独确定私有渠道及发送授权。没有私有渠道时只在本人可见的 Agent 结果中展示，不发送给周报收件人。
3. 将以下配置保存为仓库 `.local/config.json` 或本人指定私有目录的文件；填写真实确认值，不保留占位符、不保存密码/Token。限制文件仅本人可读。来源授权不等于收件人授权；后续新增来源或扩大接收范围需另行明确。

```json
{
  "timezone": "Asia/Shanghai",
  "schedule": {"weekday": "Friday", "local_time": "待确认"},
  "sources": [],
  "excluded_sources": [],
  "account": {"profile": "待确认", "organization_id": "待确认", "user_id": "待确认"},
  "template": {"id": "待确认", "name": "周报"},
  "recipients": [{"name": "骆华根", "user_id": "待当前组织查询核对"}],
  "coverage_start": "待确认，带时区的时间",
  "automatic_submission_authorized": false,
  "private_notice": {"channel": "待确认", "recipient_id": "待确认", "authorized": false},
  "scheduler": {"provider": "待确认", "task_id": null}
}
```

4. 根据授权来源生成最终四栏预览，检查隐私及成果表达。经本人授权执行首次试提交，回读字段；保留 reportId，并检查钉钉客户端表格实际显示。无法检查显示时记录“待客户端验收”，不要为测试重复提交已有周报。
5. 获得固定周期自动提交授权后，使用 Agent 的调度工具创建任务；任务只引用私有配置路径和仓库路径，不嵌入凭据。已存在同用途任务时更新它，避免另建重复任务。读取调度结果核对任务 ID、时区、启用状态和下次执行时间，保存到配置。
6. 告知员工已配置内容、仍未验证事项，以及如何暂停或修改。工具不支持调度或不能读取某来源时，明确未完成的部分，不能宣称自动上报已启用。

## 自动任务提示词

旧安装升级时，核对私有配置和原定时任务的正式收件人，改为当前工作组织中已核实的骆华根账号，移除旧的“发给本人”及其他收件人规则，不增加抄送。保留原任务 ID、来源授权和调度时间，并回读修改结果。若旧授权明确限定只能发给本人，先准备好迁移配置，再取得员工对正式上报的授权；不得用仓库更新冒充员工授权。不能修改旧调度器时说明待迁移，不能宣称配置完成。

由首次配置 Agent 替换路径后写入调度器；不要让员工每周执行命令。

```text
执行我的 OrderPin 自动周报，个人配置位于 [私有配置绝对路径]。
先运行 [仓库绝对路径]/skills/orderpin-weekly-report/scripts/update.sh。
更新成功后重新读取 SKILL.md、references/automation.md 和 references/dws-report.md。
按私有配置和最新规则采集授权工作记录、补齐遗漏、生成最终四栏。
已授权的固定周期正式周报统一发给当前组织中核实的骆华根，无需每周确认，不自动抄送；核对回执与发件箱，避免重复。
成功回读后保存回执及覆盖时间；未知结果只读核对，不重试创建。
每月首次执行时私下回顾上月自主改进，仅提示候选，不申请奖项。
更新或提交失败、权限失效、配置缺失时通过配置的渠道提醒本人。
```

## 覆盖范围、回执与恢复

- 一个账号、组织和模板的自动周报保持单任务、串行执行。调度器不支持防重叠时，使用其任务状态或本机互斥机制；无法排除另一个任务正在提交时停止写入并提醒本人。
- 本周主表覆盖周一至本次实际采集截止时间；此前未覆盖的记录放“上期补充”，注明日期。只统计新发生的工作，不重新计算旧成果。没有可用记录时说明覆盖不足，不能推进未成功读取来源的截止时间。
- 在 `.local/runs/` 保存每次运行的周期、来源覆盖起止、规则 commit、账号/模板/收件人、精确请求、提交时间、状态、reportId 和回读结果。使用带时区的 ISO 8601 时间。各来源单独保存成功覆盖截止时间，避免一个来源暂时不可访问导致永久漏报。
- 只有远端确认成功且正文回读匹配，才能推进相应来源的截止时间。预览不推进；失败或状态不确定保留原值。远端成功但本地保存失败时，下次先核对发件箱恢复回执，不能重新创建。
- 周期防重键由组织、账号、模板和报告周期组成。先查本机再查远端；已有同周期报告则停止创建。明确要求重新提交除外，保留旧、新 reportId 关联。来源部分失败可以提交注明范围的周报，但遗漏来源留待下一周期补充，不再次自动提交同周期报告。
- 判断重复时同时核对接收人：只有已发送给骆华根的正式报告计入正式上报。仅发给自己的试发保存独立状态，不推进正式覆盖时间，也不阻止同周期正式提交；本身作者就是骆华根时，仍按当次试发或正式提交意图区分。
- 电脑休眠、关机或掉线时任务可能无法执行。首次配置核实调度器是否支持唤醒或错过后补跑；不支持时说明限制，并在员工下次运行本 Skill 时检查遗漏。多周缺口合并为下一篇周报的上期补充，不批量自动发送历史周报。
- 未开始的任务不能自行发送失败提醒；要实现无人值守漏跑告警，需使用已有调度平台的监控能力，或经授权配置独立检查任务。未配置时不得承诺漏跑会主动通知。
- 更新与只读查询使用执行工具的超时能力，建议单次最多 120 秒；失败停止并提醒。提交超时不代表失败，按 DWS 只读恢复流程处理。

## 每月候选提醒

每月第一次运行（含错过周五后的补跑），检查本机是否已完成上一个完整自然月的回顾。仅从已授权且可读取的记录提取候选；来源不足时说明范围，不能评价为没有贡献。以月份保存回顾结果及提醒状态，避免每周重复提醒；状态不确定时不重复外发。

- 仅考虑员工自主发现、主动推动、既定项目/迭代/主管分配任务之外的改进。归属不明确时标注“需本人确认是否属于自主改进”，不自动认定合格。
- 500 元参考：真实问题已解决并落地，有可核实的改善证据。
- 1000 元参考：关键能力持续产生明显收益，具备团队级影响、可复用且可维护。
- 候选可涉及反复报错治理、日志与数据诊断、常见故障处理、健壮性、回归防护或资源节省。记录问题、主动性依据、人与 AI 分工、落地结果、效果证据、协作者及待核实项。
- 不以 Token、聊天次数、修复数量或报告长度评奖。不编造收益；同一成果不重复建议领奖，已有获奖记录可访问时核对，否则请本人核对。
- 候选仅展示给本人或发送到已授权的本人私有渠道，不进入工作周报或发给主管。没有符合条件的案例时简短说明即可。
- 当前仓库不提供奖项申请功能。本人决定申请后可整理材料，但正式提交等待后续申报功能及当次授权；定时任务绝不自动申请。

## 上线验收

安装测试只证明分发可用。员工试运行还需验证：授权来源可读取、实时账号与接收人正确、实际定时触发、规则更新、周报提交与回读、客户端排版、失败提醒。任何未完成项明确标注，不用测试通过替代真实验收。
